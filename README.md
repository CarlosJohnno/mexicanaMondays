# Mexicana Mondays 🐿️🎾

The Monday-night padel app: Americano or Mexicano pairings, live scoring,
all-time leaderboard, match history, light and dark mode — and a squirrel problem.

**Live site:** deployed on Netlify (drag this folder onto the site's
Deploys page, or push to GitHub once auto-deploys are linked).

## How it's built

One file. `index.html` contains the whole app — markup, styles, and logic.
Data lives in Supabase (Postgres) with four tables:

| table      | what it holds                                        |
|------------|------------------------------------------------------|
| `profiles` | one per player: name + 4-digit PIN (hashed)          |
| `matches`  | one per night: code, status, courts, `hidden_at`     |
| `players`  | who played in which match (links profile ↔ match)    |
| `games`    | every game: teams, scores, round, court              |

## Formats

**Americano** (the original): the whole draw is fixed at the start from
`SCHEDULES` (seat numbers per round/court, generated by
`tools/gen_schedule.js`). Everyone partners everyone exactly once, so the
number of rounds follows from the head-count. Odd game totals (11, 12, 13
and 14 players on 2 courts) leave one round with a single game; the app
labels the free court so nobody pulls the next round forward.

**Mexicano**: only round 1 is random. After every round the standings set
the next: 1st & 4th play 2nd & 3rd on court 1, 5th to 8th on court 2, and so
on. Sit-outs rotate (fewest sit-outs first, then longest ago). The host
picks how many rounds to play. Whoever saves the last score of a round draws
the next one; a unique index on `games(match_id, round, court)` stops two
phones drawing it twice.

## Banter

Every live match card carries one line of abuse derived from the numbers
(`banterPre` / `banterPost` in the CORE block): exact rematch records, a
pair's record together, individual head-to-heads, streaks tonight and
overall, and the gap in average points. History is fetched once per match
(`loadHistoryForBanter`) and the line is seeded on the game id, so every
phone shows the same thing. Saving a score shows the post-result line as a
toast, and the final screen gets a closer. Templates live in those two
functions; edit freely, keep the minimum sample sizes.

## Tests

```
node tools/test_core.js                     # pure logic: schedules, Mexicano draw, insights
MM_DUMP=dump.json node tools/test_core.js   # plus checks against a real data export
npm i playwright @supabase/supabase-js && node tools/smoke.js   # full UI run-through against a mock Supabase
```

A match with `hidden_at` set is invisible everywhere (history,
leaderboards, discovery). Cancelling a match sets this — nothing is ever
deleted, so anything can be restored from the database.

## Making changes

1. Edit `index.html` (or ask Claude to).
2. If the database schema needs to change, add a new numbered file in
   `sql/` — never edit an old one — and run it in
   Supabase Dashboard → SQL Editor **before** deploying the app change.
3. Deploy: push to GitHub (auto-deploy) or drag the folder onto Netlify.

## Keys — what's safe here

The `SUPABASE_URL` and the **publishable** key inside `index.html` are
designed to be public; every visitor's browser uses them. What must
**never** be committed to this repo or pasted into the app:
the `service_role` / secret key, database passwords, or personal access
tokens. Those stay in the Supabase dashboard.

## History

Every change is a git commit. To see what changed and when:
GitHub → the repo → Commits. Any old version can be restored from there —
